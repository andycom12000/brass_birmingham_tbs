第三部分：Lua 腳本架構與自動化功能

集中式 Global Script + require 模組化

1. 模組架構

-- Global Script 模組結構
Global.lua
├── GameState.lua
│   遊戲狀態管理（玩家資料、回合、時代、分數）
├── Setup.lua
│   自動設置（依人數配置地圖、洗牌、發錢）
├── TurnManager.lua
│   回合流程、行動順序、花費追蹤、順序排序
├── Actions.lua
│   6 種行動邏輯（Build/Network/Develop/Sell/Loan/Scout）
├── Validation.lua
│   合法行動判斷、高亮提示可用位置
├── Market.lua
│   煤炭/鐵礦市場價格管理、資源購買
├── Scoring.lua
│   中期計分（運河時代結束）、終局計分
├── EraTransition.lua
│   時代轉換（清除運河/Lv1 建築、重新洗牌）
├── SaveLoad.lua
│   序列化/反序列化遊戲狀態
└── Lang.lua
    多語言文字管理（英文/繁體中文）

3. 自動化功能

🎲 自動設置 Setup
  • 依玩家人數調整地圖（移除城市/連結）
  • 隨機抽取商人 Tiles 並放置
  • 洗牌並發牌（8 張/人）
  • 發放起始金額 £30
  • 放置煤炭/鐵礦至市場
  • 隨機決定起始玩家順序
🔄 回合管理 TurnManager
  • 追蹤當前行動玩家
  • 每回合 2 個行動，每個行動打 1 張牌
  • 自動累計花費金額至計數器
  • 回合結束自動補牌
  • 全部玩家完成後依花費排序
  • 計數器歸零，進入下回合
✅ 合法行動提示 Validation
  • Build：高亮可建造的城市格位
  • Network：高亮可連結的路線
  • Sell：高亮可銷售的建築
  • Develop：高亮可升級的產業
  • 使用 highlightOn() 物件發光提示
  • 非法操作彈出提示訊息
⚡ 資源自動扣除 Market
  • 建造時自動計算煤炭/鐵礦需求
  • 優先從相連建築取得（免費）
  • 不足時從市場購買（扣錢+移除 Token）
  • 市場價格隨供給自動更新
  • 啤酒需求自動從最近來源消耗
🔀 時代轉換 EraTransition
  • 偵測運河時代牌庫耗盡
  • 自動執行中期計分
  • 移除所有運河連結 Tile
  • 移除所有 Level 1 建築 Tile
  • 重新洗牌（鐵路時代牌庫）
  • 發牌、重置市場
🏆 計分 Scoring
  • 已翻面建築的 VP
  • 連結 VP（相鄰已翻面建築數量）
  • 收入等級轉換為 VP（終局）
  • 自動計算並更新計分軌
  • 終局顯示最終排名

4. 事件流程（以 Build 為例）

1
玩家從手牌中打出一張卡到棄牌堆
onObjectEnterZone(棄牌區)
2
腳本辨識卡牌類型，高亮合法建造位置
Validation.getValidBuildSpots()
3
玩家將建築 Tile 放到高亮位置
onObjectDropped(Snap Point)
4
腳本自動扣除金錢 + 資源（煤/鐵）
Market.consumeResources()
5
放置資源 Token 到建築上（如煤礦產煤）
Actions.placeResources()
6
更新 GameState、計數器花費、剩餘行動 -1
TurnManager.endAction()

5. 存檔/讀檔

  • onSave() — 將 GameState 序列化為 JSON 字串，TTS 自動保存
  • onLoad(save_state) — 從 JSON 還原 GameState，重建所有 UI 狀態
  • 物件位置由 TTS 自動保存，腳本只需保存邏輯狀態
  • 載入後重新綁定所有物件參照（GUID mapping）

6. 多語言系統

  • Lang.lua 管理所有 UI 文字的中英文對照表
  • 腳本產生的提示訊息（如「輪到你的回合」/「Your turn」）依語言設定顯示
  • 透過桌面上的語言切換按鈕（一個 Custom Tile）全局切換
  • 幫助卡翻面切換語言、規則書準備 2 本
